# AO Forge First Public Release Checklist

This checklist is for the first public AO Forge release. It must stay
public-safe: Do not paste local absolute paths, private tokens, or excluded handoff notes
into release evidence, release notes, pull requests, or GitHub release text.

Use placeholders such as `<tag>` and `<run-id>` in public notes until the value
is intentionally public.

## Preconditions

- `main` is clean and synced with `origin/main`.
- Required branch protection is active for `main`; see
  `docs/release/BRANCH-PROTECTION.md`.
- Post-merge CI is green on Ubuntu, macOS, and Windows.
- Post-merge `Release Preview` is green.
- The `Release Rehearsal` workflow is available and read-only.
- Release contracts validate from a clean checkout:
  - `docs/contracts/release-preview-audit-v0.1.schema.json`
  - `docs/contracts/release-preview-inspect-v0.1.schema.json`
  - `docs/contracts/release-artifact-inventory-v0.1.schema.json`
  - `docs/contracts/release-attestation-plan-v0.1.schema.json`
  - `docs/contracts/release-evidence-bundle-v0.1.schema.json`

## Tag Decision

1. Choose the intended public tag as `<tag>`, for example `v0.1.0`.
2. Confirm `<tag>` has not already been published for another commit.
3. Confirm the release commit is the current `origin/main` HEAD.
4. Record the intended `<tag>` and commit SHA in the operator notes.
5. Do not create or push the tag until Release Rehearsal evidence has passed and
   been reviewed.
6. For releases after `v0.1.0`, create a signed annotated tag that points at the
   reviewed release commit:

   ```sh
   git tag -s <tag> <commit-sha> -m "AO Forge <tag>"
   git tag -v <tag>
   git push origin <tag>
   ```

## Local Release-Readiness Gate

Run this from a clean checkout before creating public release artifacts:

```sh
git diff --check
go test ./... -count=1
go vet ./...
go build -o /tmp/ao-forge-release-smoke ./cmd/forge
/tmp/ao-forge-release-smoke doctor --foundation docs/foundation/foundation-baseline.v0.1.json
/tmp/ao-forge-release-smoke contract validate --schema docs/contracts/release-preview-audit-v0.1.schema.json --document examples/release-preview/dirty-workspace-blocked.audit.json
/tmp/ao-forge-release-smoke contract validate --schema docs/contracts/release-preview-inspect-v0.1.schema.json --document examples/release-preview/dirty-workspace-blocked.inspect.expected.json
/tmp/ao-forge-release-smoke contract validate --schema docs/contracts/release-artifact-inventory-v0.1.schema.json --document examples/release-preview/release-artifact-inventory.v0.1.example.json
/tmp/ao-forge-release-smoke contract validate --schema docs/contracts/release-attestation-plan-v0.1.schema.json --document examples/release-preview/release-attestation-plan.v0.1.example.json
/tmp/ao-forge-release-smoke contract validate --schema docs/contracts/release-evidence-bundle-v0.1.schema.json --document examples/release-preview/release-evidence-bundle.v0.1.example.json
/tmp/ao-forge-release-smoke artifact verify-checksums --manifest examples/release-preview/checksums.txt
gitleaks detect --source . --redact --verbose
gitleaks dir . --redact --verbose
AO_FORGE_RELEASE_PREVIEW_TAG=<tag> AO_FORGE_RELEASE_PREVIEW_OUT=/tmp/ao-forge-first-public-release scripts/release-preview-dry-run.sh
python3 -m json.tool /tmp/ao-forge-first-public-release/release-preview-inspect.json >/dev/null
```

Keep the generated local audit out of public commits unless every path and
metadata field is intentionally public.

## Artifact Checklist

Use `examples/release-preview/release-artifact-inventory.v0.1.example.json` as
the expected artifact inventory for the first public release.

Required release evidence:

- release archives for the supported platforms in the inventory;
- `checksums.txt` generated by `forge artifact checksums`;
- release preview audit and inspect JSON for `<tag>`;
- release attestation plan from
  `examples/release-preview/release-attestation-plan.v0.1.example.json`;
- release evidence bundle and its GitHub Artifact Attestation from
  `release-evidence-bundle.json` and
  `release-evidence-bundle.attestation.json`;
- no ad hoc local paths or private machine state in public release notes.

Every artifact in the inventory must have a SHA-256 checksum and must be bound
to the attestation plan before publishing.

## Release Rehearsal

Run the `Release Rehearsal` workflow manually with `<tag>` before any public
publish operation. Review the uploaded `release-rehearsal-evidence` artifact and
confirm:

- audit status is `passed`;
- inspect status is `passed`;
- failed checks count is `0`;
- tag equals `<tag>`;
- commit equals the intended release commit;
- `mutates_releases` is `false`;
- `network_required` is `false`;
- `checksums.txt` is present in the artifact evidence;
- the workflow read back the artifact inventory and attestation plan.

If any item fails, stop the release and open a hardening issue or PR before
retrying.

## Publish Decision

Only publish when all of these are true:

- local release-readiness gate passed;
- `Release Preview` passed on `main`;
- `Release Rehearsal` passed for `<tag>`;
- `<tag>` is an existing signed annotated tag that resolves to the intended
  release commit;
- artifact inventory and attestation plan were validated;
- checksum manifest was reviewed;
- release notes contain no private local paths, tokens, or excluded handoff
  material;
- a maintainer explicitly approves the publish in the release notes or PR.

Use the `Release Publish` workflow for the first draft GitHub release. Provide
the passing `Release Rehearsal` run ID for `<tag>`, keep `confirm_publish` set
to `false` until the final review is complete, then rerun with
`confirm_publish=true`. The workflow creates a draft release only; review the
uploaded `release-publish-evidence` artifact before making the release public.

The first public release should be treated as controlled release, not broad
production-stable adoption.

## Post-Release Verification

After publishing:

1. Run the `Release Verify` workflow for the published `<tag>`.
2. Confirm the public tag is signed, annotated, and points at the intended
   commit. For `v0.1.0` only, dispatch with `require_signed_tag=false` because
   that release predates this policy.
3. Confirm every expected artifact from the inventory is attached.
4. Confirm `checksums.txt` matches every attached artifact.
5. Confirm attestation evidence is attached or linked according to the
   attestation plan.
6. Confirm `release-evidence-bundle.json` validates and its GitHub Artifact
   Attestation verifies against the release commit. For `v0.1.0` only, the
   workflow may be run with `require_evidence_bundle=false` because that release
   predates the bundle asset; future releases must keep the default `true`.
7. Confirm public release notes mention the supported platforms and preview
   status.
8. Run a fresh install or binary smoke test from the published artifact.
9. Record the GitHub Actions run URLs for CI, Release Preview, and Release
   Rehearsal in maintainer notes.
10. Record the `Release Publish` run URL and confirm it produced a draft release
   before any public release publication.

## Rollback Plan

If the public release is wrong:

1. Run the `Release Rollback` workflow with `rollback_action=audit-only` to
   capture release metadata and operator evidence before mutation. This path is
   read-only and should complete without `production-release` environment
   approval.
2. If user impact requires it, rerun `Release Rollback` with
   `rollback_action=mark-prerelease` or `rollback_action=mark-draft`; these
   mutating paths require `production-release` environment approval.
3. Publish a correction note that states the affected `<tag>` and artifact names.
4. Do not silently replace artifacts unless the replacement policy is documented
   in the release notes.
5. Create a new corrective tag when artifacts or checksums changed.
6. Rerun Release Preview and Release Rehearsal for the corrective tag.
7. Keep the original evidence for auditability.

Never delete evidence merely to hide a bad release. Preserve the trail, then
ship a corrected release.
