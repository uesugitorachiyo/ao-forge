# AO Forge v0.1.3 Release Notes

AO Forge v0.1.3 extends the production-stable v0.1.2 release foundation with
durable GoalRun contracts, AO2 Pulse readiness handoff controls, retained
evidence policy checks, and a repository production-readiness audit gate.

The production-stable claim for this release is valid only after the
Production Promotion workflow passes for `v0.1.3`. Until then, treat `v0.1.3`
as a release candidate.

## Release Identity

- Tag: `v0.1.3`
- Repository: `github.com/uesugitorachiyo/ao-forge`
- Release status before promotion: release candidate
- Release status after passing Production Promotion: production-stable for
  solo-operator adoption

## What Changed Since v0.1.2

- Added durable GoalRun contracts for AO Forge task lifecycle tracking.
- Added GoalRun validation, transition checks, guarded updates, and update audit
  evidence.
- Added AO2 Pulse GoalRun loop documentation and a readiness entrypoint.
- Added GoalRun evidence freshness, linting, retained evidence metadata, and
  negative fixtures.
- Added retained readiness audit provenance checks and stale-evidence blocking.
- Added production-readiness audit command and CI gate.
- Added retained evidence cleanup dry-run evidence to the production-readiness
  artifact.
- Kept public provenance evidence mandatory for promotion-related controls.

## Supported Artifacts

The expected public artifact inventory defines these required platforms:

- `linux-amd64`: `dist/ao-forge_Linux_x86_64.tar.gz`
- `darwin-arm64`: `dist/ao-forge_Darwin_arm64.tar.gz`
- `windows-amd64`: `dist/ao-forge_Windows_x86_64.zip`

Each artifact must be covered by `checksums.txt` and by the release attestation
plan before publishing.

## Verification Evidence Required

- Post-merge CI on Ubuntu, macOS, and Windows must pass for the release commit.
- Post-merge Release Preview must pass for the release commit.
- Release Rehearsal must pass for `v0.1.3` before Release Publish runs.
- Release Publish must create a reviewed draft release for `v0.1.3` before any
  public release publication.
- Release Verify must pass with default signed-tag and evidence-bundle gates.
- Release Install Verify must pass for the public release assets.
- Release Rollback audit-only must pass without mutating the release.
- Production Promotion must pass before these notes describe `v0.1.3` as
  production-stable.
- Release preview evidence for `v0.1.3` must report `status=passed`,
  `failed_checks=0`, `mutates_releases=false`, and `network_required=false`.

## Operator Notes

Before publishing, confirm that:

- the public tag is signed by an active signer and points at the intended commit;
- the uploaded archives match the supported artifacts above;
- `checksums.txt` matches every uploaded archive;
- attestation evidence is attached or linked according to the attestation plan;
- these release notes contain only public repository information.

## Known Limitations

- Production-stable status is scoped to solo-operator adoption.
- Broader multi-user or unattended production infrastructure still needs
  additional product-surface hardening and operational soak evidence.
- AO2 Pulse should remain gated by GoalRun readiness evidence and should not
  bypass AO Forge release or evidence policy checks.
